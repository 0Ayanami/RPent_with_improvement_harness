# 原生 RPent：LIBERO 五任务模型、推理强度与 Codex 额度开销对照

本记录包含四批普通 Harness-VLA 实验，通过 Windows 本地 Codex 和 SSH 调用服务器 LIBERO/Pi0.5/SAM3。没有执行 memory 编辑、PPC、Compose、反思或 meta 检索。A/B 使用 `gpt-6.1-sol/xhigh` 执行标准 `libero_object` 的 task 0–2 和 task 3–4；C 使用 `gpt-6.1-sol/low`，D 使用 `gpt-6-astra/low`，分别执行 task 0–4，均为 seed 0。共五个不同任务、十五个有效回合；D 另外保留四次额度中断，额度恢复后仅重试未完成的 task 1–4，不按能力表现筛选回合。A/B/C/D 执行版本分别为 `9f2536c`、`2dd0acf`、`be51c18`、`1724a6f`，这些版本间仅增加研究文档，执行源码相同。

## 输入与测量

执行模型为 A/B/C 的 `gpt-6.1-sol` 和 D 的 `gpt-6-astra`，A/B 的推理强度为 `xhigh`，C/D 为 `low`；每回合限制 100 个模型响应、5000 秒、10000 个准入环境步和 240 次 VLA 调用。模型权重和服务沿用[部署指南](harness_vla_codex_libero_smoke.md)。所有有效回合使用相同原始 memory，来源为 `RLinf/RPent-memory@47f301ef33bf8d0e8c770342f16b3c39c6a0e8c1/libero/GPT_5.5_xhigh`，快照摘要均为 `sha256:5996d7db1b006cfd5f9a86fca8441f0dfe3a90bd1dd76084df28a37d4e9a8071`，执行后完整性核验通过。语料名称中的 `xhigh` 表示其历史生成配置，不随本轮执行推理强度改变。

在现有 SDK 事件观察器外增加被动计时，记录本地事件到达的单调时钟、UTC、工具事件和 token 更新；不改变提示、工具、模型参数或动作策略。输入/缓存/输出/推理计数全部与每个有效回合 transcript 的最终 SDK 用量核对一致。CSV 保存逐响应 token 增量及累计值、逐工具时长、全部原生操作 span；无 memory improvement 机制参与执行。

## 首批三个任务分析

1. 当前主要时间花在云端决策交互链。71.31% 的 trial 时间没有被 MCP 工具活动覆盖，而 22 次原生 VLA 预测合计不足总时间的 1.1%。仅加速 Pi0.5 预测，无法解决目前几分钟的单任务延迟；应继续区分模型生成、网络和排队，再比较交互轮数与上下文组织。
2. 输入量大主要伴随重复上下文与历史积累。三个任务首次响应输入约 2.5 万 token，最后响应分别约 9.5、9.9、9.2 万；多轮累计产生数百万输入，其中大部分命中缓存。不能把累计输入量当作独立信息量，也不能仅凭它推算实际收费。
3. 三任务共 42 次文件读取和 52 次反投影，占工具调用约 67.6%。它们单次服务较快，但跨响应的决策交互仍会增加整体等待。若后续做性能优化，应独立实验批量只读调用、减少重复资料读取等策略，不在本轮改动原生行为。
4. task 2 出现一次文本分割失败，随后用手工像素与反投影恢复，最终成功；它仍比 task 0 更快。因此不能仅以失败工具数判断总成本，响应轮数、输出量和请求等待也需同时观察。
5. 这三个任务属于同一 Object suite、相同放置目标，样本小且较相似。3/3 仅为本次观测，不是完整 LIBERO 成功率，也不能用于宣称原始 memory 优于或劣于 improvement memory。

## 开销变化发生在哪里

合并 A/B 的五个 `xhigh` 任务后，与 C 的相同五任务配对：平均 trial 时延由 **312.00 秒降至 184.17 秒，下降 40.97%**；输入 token 总量下降 34.89%，输出下降 57.18%，其中推理输出下降 93.33%。模型响应由 109 次降至 79 次，工具调用由 235 次降至 182 次。两档各观察到 5/5 原生成功。

平均每任务节省约 127.83 秒，其中会话内非 MCP 活动区间从 217.38 秒降至 96.42 秒，减少 120.97 秒，约占观测节省的 94.6%；MCP 工具活动从 66.82 秒降至 59.92 秒，减少 6.89 秒；SDK 会话外时间约 27.8 秒，基本不变。因此本次主要节省发生在云端决策交互相关区间，并非环境启动或 VLA 预测。但该区间仍混合模型、网络和排队，不能把 120.97 秒全部归因为模型计算。

C 的 VLA 预测从 37 次增加至 40 次，平均单次 0.437 秒、合计 17.49 秒；预测次数没有减少，但总时延明显降低。更低的推理输出、较少的响应与工具交互共同伴随了当前时延改善，不能只用 GPU 推理速度解释。

C 输入缓存占比为 91.50%，低于前两批合计的约 93.79%；非缓存输入从 467,277 降至 416,138，下降约 10.94%，小于累计输入的降幅。因此不能把“输入 token 少 34.89%”直接解释为收费或订阅额度少 34.89%。各批平均值、细分 token 和时延分区均见开头总表。

只有 task 3、4 在两档都具有完整额度快照：`xhigh` 的 5 小时账号观测增量合计 +18 个百分点，`low` 为 +13；周窗口两档都观测到 +2。后者体现了整数百分比的粗粒度，不能据此认定两档周额度实际消耗相同。不同执行时间段的账号并发活动也无法剥离，故额度数据只作观测，不给出精确费用节省率。

本次每个任务/档位仅一个回合，任务均为 Object suite 的相似抓放操作，且按时间顺序执行，云端排队与服务负载可能变化。这支持继续研究 `low` 的成本优势，但没有证明在其他任务、扰动或完整 benchmark 上无性能损失。
