# 原生 RPent：LIBERO seed 0 五任务开销分析

本记录包含两批普通 Harness-VLA 实验，通过 Windows 本地 Codex 和 SSH 调用服务器 LIBERO/Pi0.5/SAM3。没有执行 memory 编辑、PPC、Compose、反思或 meta 检索。首批预声明标准 `libero_object` 的 task 0、1、2，续跑预声明 task 3、4，各执行 seed 0 一次，未按结果筛选任务。首批执行版本为 `9f2536c5ed4148bc3637ca114cb610127bf7ab24`，续跑为仅增加研究文档后的 `2dd0acfd50bbb81917a85611c661e8382a6fa22b`；执行源码相同。

## 输入与测量

执行模型为 `gpt-6.1-sol/xhigh`，每回合限制 100 个模型响应、5000 秒、10000 个准入环境步和 240 次 VLA 调用。模型权重和服务沿用[部署指南](harness_vla_codex_libero_smoke.md)。三个任务使用相同原始 memory，来源为 `RLinf/RPent-memory@47f301ef33bf8d0e8c770342f16b3c39c6a0e8c1/libero/GPT_5.5_xhigh`，快照摘要均为 `sha256:5996d7db1b006cfd5f9a86fca8441f0dfe3a90bd1dd76084df28a37d4e9a8071`，执行后完整性核验通过。

在现有 SDK 事件观察器外增加被动计时，记录本地事件到达的单调时钟、UTC、工具事件和 token 更新；不改变提示、工具、模型参数或动作策略。输入/缓存/输出/推理计数全部与每个 transcript 的最终 SDK 用量核对一致。CSV 保存逐响应 token 增量及累计值、逐工具时长、全部原生操作 span；无软件内存优化机制参与执行。

## 首批三个任务分析

1. 当前主要时间花在云端决策交互链。71.31% 的 trial 时间没有被 MCP 工具活动覆盖，而 22 次原生 VLA 预测合计不足总时间的 1.1%。仅加速 Pi0.5 预测，无法解决目前几分钟的单任务延迟；应继续区分模型生成、网络和排队，再比较交互轮数与上下文组织。
2. 输入量大主要伴随重复上下文与历史积累。三个任务首次响应输入约 2.5 万 token，最后响应分别约 9.5、9.9、9.2 万；多轮累计产生数百万输入，其中大部分命中缓存。不能把累计输入量当作独立信息量，也不能仅凭它推算实际收费。
3. 三任务共 42 次文件读取和 52 次反投影，占工具调用约 67.6%。它们单次服务较快，但跨响应的决策交互仍会增加整体等待。若后续做性能优化，应独立实验批量只读调用、减少重复资料读取等策略，不在本轮改动原生行为。
4. task 2 出现一次文本分割失败，随后用手工像素与反投影恢复，最终成功；它仍比 task 0 更快。因此不能仅以失败工具数判断总成本，响应轮数、输出量和请求等待也需同时观察。
5. 这三个任务属于同一 Object suite、相同放置目标，样本小且较相似。3/3 仅为本次观测，不是完整 LIBERO 成功率，也不能用于宣称原始 memory 优于或劣于 improvement memory。

## 原始产物、失败尝试与复跑

有效实验目录为 `logs/native-baseline-seed0-20261030-02/`。重点文件：`analysis.json`、`responses.csv`、`tool-calls.csv`、`native-spans.csv`、`plan.json`、`batch.json`，以及每个 `task-N/episode/` 的 `transcript.json`、`event-timing.jsonl`、原始 SDK stream、`spans.json` 和原生审计。服务器原始仿真记录仍在项目 worker 目录；两端保存本轮审计归档。

首次计时尝试位于 `logs/native-baseline-seed0-20261030/`，因新增记录器未序列化 SDK 枚举，在三个回合动作开始前停止，均已清理。三次调用累计 112.08 秒；没有观测到完成的模型响应，不能据此断言云端实际消耗为零。这些尝试不纳入上表有效结果，也未删去。

有效执行脚本保存在 `run-executed.py`。该版本没有将观察器生成的可读日志文本返回给调用者，导致便于阅读的 `codex_*.txt` 为空；完整原始 SDK JSON、结构化 transcript、token 和事件时间戳均已保存并交叉核验，模型输入及工具执行未改变。供复跑的 `run.py` 已恢复这项返回值；不据此宣称重新跑过一轮。

复跑时先按部署指南建立服务与 SSH 隧道，把 `run.py`、`analyze.py` 复制到 `logs/` 下的新目录，然后在仓库根目录执行以下命令。脚本会使用其所在目录保存结果，拒绝覆盖现有任务输出：

```powershell
$env:HTTP_PROXY = 'http://127.0.0.1:7890'
$env:HTTPS_PROXY = 'http://127.0.0.1:7890'
$env:NO_PROXY = '127.0.0.1,localhost'
.venv/Scripts/python.exe -u -B logs/<新目录>/run.py
.venv/Scripts/python.exe -B logs/<新目录>/analyze.py
```

本次仅新增离线观测脚本和研究记录，未修改受控执行代码。按 `verify-change`、`docs-check` 核验统计一致性、语料摘要、文档与现有格式检查，不重复跑与本次无关的单元测试矩阵。
